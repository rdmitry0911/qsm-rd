Hi guys, another update on stock PVE support, access through NAT and the remaining text-sharpness issue.

There is now a standalone package for official PVE 9, without installing rebuilt Proxmox packages. The patched shared-platform integration remains a separate upstream proposal.

I've also added an optional gateway for a node behind a router with only TCP 8006 forwarded. PVE HTTPS, QSM signalling and authenticated TURN over TCP share that port, so no extra public signalling port or incoming UDP range is needed. The browser uses the public hostname and port of the PVE page; the relay is configured with the node's LAN address. Direct UDP remains available where the network allows it, as TCP can add latency under packet loss.

A clarification about encryption: the UI, login and signalling use HTTPS, video/audio use SRTP, and input/clipboard use DTLS-protected data channels. The outer TURN connection currently uses plain TCP, not TURN/TLS. Its service messages are visible, while the desktop, sound and input payloads remain encrypted between browser and QSM. This is not an HTTPS-only transport.

The unnecessary bitrate reduction described in my previous post is fixed. A single lost packet in a short receiver report no longer makes the controller cut the target from 8 to 6 Mbit/s. With adaptation enabled, H.264 NVENC and HEVC NVENC static-text tests with occasional injected loss kept the target and text stable. Sustained congestion still lowers the bitrate and recovery returns it to the configured maximum. A large sudden bandwidth drop can still cause brief freezes.

I've checked VM and LXC video/reconnect in Chrome and Firefox in a controlled NAT lab allowing only TCP 8006 plus established traffic. I've also checked the gateway on my regular node with Firefox and Chromium using a test LXC. Those node checks were over LAN; they are not a completed test through my own Internet router.

The gateway is still an experimental, explicitly enabled single-node profile. It changes the PVE proxy listener and affects external SPICE after its service restarts. Please read the installation and rollback notes, especially for an existing patched setup or custom proxy configuration.
