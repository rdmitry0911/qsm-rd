Implementation/proposal update, 2026-10-22

The original description predates the discussion with Alexandre Derumier on pve-devel. The proposed native integration now uses a private per-VM D-Bus bus owned by qemu-server, based on his shared foundation. QSM attaches as a display consumer; capture, encoding and WebRTC remain in a separate package. This replaces my original p2p=yes/getfd/add_client proposal. The foundation, console API and UI changes are kept as separate series for review.

The proposed opt-in is dbus-display: 1, with rendering options remaining in vga and a dbus driver for audio0. The configuration and service/API boundary are still proposals, not agreed upstream interfaces.

Current discussion and native review material:
