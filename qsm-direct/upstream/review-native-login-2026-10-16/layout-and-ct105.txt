Native SDDM layout follow-up and CT105 migration, 2026-10-16
==========================================================

Packages: qsm-{pve-direct,pve-direct-lxc,console-guest} 0.4.0+shared12;
optional private qsm-console-sddm 0.21.0+qsm2 (Ubuntu 24.04 / Qt 5).
This extends the shared11 baseline in qualification.txt. Its old layout
limitation and statement that CT105 was not migrated are superseded here.

Implementation
--------------
The native SDDM Wayland backend populates its original keyboard model from
the installed XKB base-layout registry. A restricted Unix API applies the
actual map through the root per-seat controller. Only root and SDDM may use
the endpoint; it accepts registered layout IDs, never compositor commands.
A desktop owns its own layout and rejects greeter changes while logged in.
Selection state is separate for each seat. A fresh greeter starts with the
first valid system XKBLAYOUT (otherwise us); releasing an idle greeter or
logging out restores that default. The desktop outer map starts with us.

New virtual keyboards upload a US map without invalidating Sway's cached
configuration. The host negotiates keyboard_sync with the native controller
and waits for input_ready before exposing a newly started media worker.
The controller forces a distinct intermediate map when the actual device
maps differ. The worker follows wl_keyboard keymaps and translates modifier
state into that map, including held keys and lock modifiers.

The private SDDM QML directory bounds its layout list to 240 pixels with
scrolling. System themes and distro QML files are unchanged. Native profile
activation now reads the distro SDDM --example-config defaults before its
administrator drop-ins: Ubuntu's compiled ubuntu-theme default is retained
when /etc/sddm.conf and drop-ins do not exist.

Limits
------
The native profile remains an opt-in Ubuntu 24.04 / Qt 5 / Plasma Wayland
qualification. The selector covers base XKB layouts; it does not configure
custom variants/options or layout-switching shortcuts. Audio/microphone
and tablet gestures were not requalified in this follow-up. No host reboot
was performed. Node 172.16.16.17 was not changed in this follow-up.

Reproduction
------------
Use browser-lab.py from this directory. QSM_LAB_VMID is restricted to 108 or
105 (default 108). QSM_TEST_ACCOUNT accepts only the named ephemeral lab
accounts, never qsm. QSM_LAB_BROWSER=firefox uses Playwright Firefox; provide
MOZ_GMP_PATH when its OpenH264 plugin needs an offline installation.
The driver additionally supports wheel (dy). To test reconnect, close the
viewer, wait for host transport cleanup, then reopen it from the PVE menu.
Credentials stay in memory; no traces or credential-bearing URLs are saved.

For the native input upload test, use disposable CT108 with seat1 showing
its ru greeter, seat2 us and one browser attached to seat1. Copy and run
keyboard-probe.py as root inside that CT. It creates and then removes only
its own additional keeper process, checks input_ready, and forks a child
with UID/GID 1000 to verify the socket's access restriction.
