the original p2p patch series, and the NVIDIA Kyber adapter fix exist.

IMPLEMENTATION FINDINGS

1. Shared qemu-server base: NOT DONE.
   The prepared qemu-server patch 2 still generates:
     -display dbus,p2p=yes,gl=...
   See patches/qemu-server/0002-*.patch:109.
   Patch 3 creates our own DBusDisplay.pm with attach_client and
   webrtc_offer, using QMP getfd/add_client and SCM_RIGHTS. It is not
   Alexandre's module that starts/stops a private daemon per VM.
   The local upstream webrtc-console branch contains the same design.

2. QSM attachment to the shared bus: NOT DONE.
   src/qemu/qemu_dbus_display.cpp:452 supports both p2p and message buses.
   That support predates the proposed port and passed local bus tests.
   However, extensions/direct_terminal/qsm_direct_terminal.py:774
   accepts only its own VM runtime socket, and the fallback address at
   line 173 is <vm-runtime>/<VMID>/qemu-display1.bus.
   The package starts its own daemon at line 803.
   The PVE webrtcproxy contract still requires a passed display fd
   (answer_webrtc at line 1832; WebRtcRequestHandler at line 1945).
   There is no implemented shared-bus attach contract with Alexandre's
   /run/qemu-server/<VMID>.dbusdisplay socket.

3. API/UI: ORIGINAL INTEGRATION EXISTS; SHARED-BASE VERSION NOT DONE.
   The viewer calls webrtcproxy and the package receives its display fd.
   The standalone add-on still uses its own TCP 8007 signalling service
   and writes display/audio arguments through its existing UI overlay.
   The prepared native UI still exposes our dbus VGA flag. No revised
   common configuration/interface is present.
   The separate media service is already packaged, but this does not
   establish its compatibility with a shared qemu-server bus lifecycle.

4. Audio: PARTIAL PREPARATION, NOT SHARED-BASE QUALIFICATION.
   qemu-server has a webrtc-console-audio branch at 67a2cc12; pve-manager
   has a matching branch at 0a2c9d1c. Both are dated 2026-10-01.
   They are absent from the exported 5+3 patch series. The server audio
   branch still combines the backend with p2p=yes. Existing add-on
   playback/microphone support does not qualify these native patches
   against Alexandre's base.

5. Kyber NVIDIA support: ADAPTER PATCH PREPARED; FULL CONSOLE UNVERIFIED.
   kyber-nvidia/0001-*.patch adds --dmabuf-readback, EGL import/readback,
   build dependencies, and use of the existing encoder path.
   Its recorded 2026-10-07 test is capture/encoding to a file on an
   RTX 3080: 1226 NVENC frames in 20 seconds, zero dropped in that test.
   This is historical evidence in the patch and follow-up, not a new
   test performed in this audit. It does not include the full Kyber
   controller/proxy/browser path or automatic controller selection of
   the new NVIDIA capture mode.

6. OpenGL 4.6 / Venus: NO REBASE WORK FOUND.
   No new common branch or updated exported series takes account of
   the dependency mentioned by Alexandre. The current fetched upstream
   QemuServer.pm has no Vulkan/Venus display option. The port must
   explicitly identify the chosen baseline/dependency and resolve this
   as part of the shared series.

REMAINING REVIEW AND VALIDATION WORK

Implementation:
  1. Extract the shared bus creation, configuration and VM start/stop
     integration from v2. Decide the opt-in setting and audio0 backend
     representation with maintainers; document them in the cover letter.
  2. Attach QSM as a client of that bus with the PVE VM.Console gate.
     Define the API-to-service request, bus ownership and session cleanup
     contract; stop provisioning a second bus for that native mode.
  3. Adapt native UI/status/viewer and clipboard/audio paths. Identify
     which standalone add-on compatibility paths remain supported.
  4. Integrate the NVIDIA capture fix with the chosen Kyber version and
     define how kycontroller selects it. Account for the Venus baseline.

Required evidence after implementation:
  - config-to-QEMU-command tests for GL/non-GL, rendernode and audio;
  - bus startup/failure/cleanup, VM stop/start and service restart;
  - two VMs on one node and concurrent WebRTC + Kyber/RDP consumers;
  - real PVE browser picture/input/resize, embedded and popup consoles;
  - denied VM.Console and positive restricted-user access;
  - playback, microphone and clipboard on the declared guest desktops;
  - full NVIDIA Kyber browser session, plus software fallback and
    AMD/Intel paths where hardware or collaborator reports are available;
  - package installation/removal and effects on supported existing VMs.
