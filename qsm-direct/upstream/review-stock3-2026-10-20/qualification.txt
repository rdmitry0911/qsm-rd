QSM Direct stock3: standalone transition, deployment checks and installation docs
2026-10-20
===============================================================================

Changes relative to stock2
-------------------------
The standalone UI now recognizes a VM's existing native dbus-display=1 when
its VGA type is supported by the terminal's shared display path. Both the
Console selector and top Console menu retain QSM access. Saving Display uses
stock VGA serialization instead of adding a private -display; private controls
are hidden for shared-display VMs. The Audio dialog retains the existing dbus
backend. These are compatibility changes for a staged UI transition only.
Existing native qemu-server is still required for those configs/VMs. This is
not an automatic reverse display conversion or removal of native dependencies.

Documentation now provides matching stock3 host-only installation commands,
direct UDP versus single-TCP-port choices, explicit router/NAT examples,
external versus node-local port distinctions, encryption boundaries, guest-only
package placement, upgrades, native transition limits, SPICE impact and rollback.
The older README's claim that the isolated-loss bug remains open is removed.
No TURN/TLS implementation is added or claimed. No new bitrate algorithm is
added beyond stock2's confirmed-loss change.

Encryption boundary and remaining limits
----------------------------------------
PVE UI/login/signalling: TLS, terminated at the gateway and re-encrypted with
certificate verification to local HTTPS backends. Media: DTLS-SRTP/SRTP.
Data channels: SCTP over DTLS between browser and QSM. The outer TURN control
connection is plain TCP. TURN service messages, temporary identifiers and relay
addresses are observable; encrypted session payloads remain protected. This is
not an all-TLS or HTTPS-only transport and does not add TURN/TLS on shared 8006.

Automatic gateway setup remains single-node stock UI, with absent/comment-only
pveproxy defaults. Native patched viewer, custom ACL/proxy configurations,
clusters and IPv6-only relay deployments are outside automatic qualification.
LISTEN_IP also affects external SPICE when spiceproxy restarts. Direct UDP is
still preferable when available; TCP retransmission and severe congestion can
add latency/freezes. The shared bitrate fix applies to all encoder paths; new
hardware loss tests from stock2 were on NVIDIA, not a repeated Intel test.
